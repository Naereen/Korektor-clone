Guide de l'application

Korektor

Assistant IA pour la correction de copies manuscrites.

Cette page reprend la documentation du projet et décrit le parcours complet, de l'import du scan au bilan des notes.

Logiciel créé par Philippe HELLUY, et modifié par Lilian BESSON (@Naereen). Mon fork est disponible sur GitHub (dépôt privé).

Fonctionnalités

  1. Numérisation et import : import direct de scans A4 ou découpage intelligent de scans A3 vers A4, puis regroupement par étudiant.
  2. Structuration du sujet : analyse du sujet et du corrigé pour générer un barème structuré avec questions, réponses attendues et points.
  3. Extraction OCR : transcription du contenu manuscrit en Markdown avec structuration assistée par LLM.
  4. Correction IA : notation assistée avec notes, commentaires, raisonnement et contexte des copies précédentes.
  5. Vérification professeur : relecture des copies, ajustement des notes et validation des corrections.
  6. Bilan : suivi des copies corrigées, des notes brutes, des notes reconverties sur 20 et visualisations exportables en PNG.

Installation

Prérequis : Python 3.12 ou plus récent et uv.

Créer l'environnement virtuel et installer les dépendances :

uv venv
source .venv/bin/activate
uv sync

Les dépendances et les groupes de développement sont déclarés dans pyproject.toml. Une installation historique reste possible avec :

uv pip install -r requirements.txt

Définir ensuite une clé API correspondant au provider utilisé, par exemple :

export UNISTRA_API_KEY="votre_cle_ici"
# ou, selon le provider :
export ILAAS_API_KEY="votre_cle_ici"

Utilisation

Lancer l'application

make run
# ou
uv run python correct_ai/app.py

L'interface est accessible sur http://127.0.0.1:5000.

Configurer un projet

  • Le dossier de travail par défaut est ./exemple.
  • Le dossier actif peut être changé depuis l'onglet Import.
  • Les fichiers principaux sont sujet.md, corrige.md et liste-etudiants.csv.
  • bareme.csv est généré depuis l'onglet Import et peut être vérifié ou modifié avant son chargement en base.

Parcours recommandé

  1. Import : sélectionner le projet, vérifier les fichiers, générer le barème et importer le PDF. Conserver l'option PDF déjà en A4 pour un scan A4 ; la décocher pour découper des feuilles A3.
  2. Découpage : valider les pages importées ou découpées et l'identification des étudiants.
  3. OCR : lancer l'extraction sur une plage de copies. La case Forcer permet de recalculer les extractions existantes.
  4. Vérif OCR : relire et corriger le texte page par page.
  5. Correction : lancer la correction incrémentale. La case Forcer permet d'écraser les corrections existantes.
  6. Vérif Correction : contrôler les réponses, les commentaires, le raisonnement et les notes.
  7. Bilan : consulter l'état global, les notes, les copies incomplètes et les graphiques de l'évaluation.

Graphiques du bilan

La page Bilan affiche les visualisations suivantes :

  • Distribution des notes / 20 : histogramme des notes finales par tranches de 1 point.
  • Difficulté des questions : pourcentage moyen de points obtenus pour chaque question.
  • Profil moyen de la classe : comparaison, question par question, entre le barème et la moyenne obtenue par la classe.
  • Dispersion par question : distributions en violon avec points individuels, boîte à moustaches et moyenne.
  • Résultats détaillés : comparaison du barème et des points obtenus par un étudiant sélectionné ou par la moyenne de la classe.

Chaque graphique peut être téléchargé individuellement en PNG. Le bouton Exporter tous les graphiques en PNG, situé en haut de la page, sauvegarde l'ensemble des graphiques dans le sous-dossier graphiques_notes/ du projet actif. Les images sont générées avec un fond blanc.

Structure des données

Base SQLite : korektor.db

La base conserve les informations nécessaires à la correction et à la validation :

  • sujet : contenu du sujet.
  • corrige : corrigé officiel.
  • bareme : questions, types, réponses attendues et points.
  • copies : métadonnées, PDF, extraction OCR et état de vérification.
  • corrections : notes LLM, notes professeur, commentaires, raisonnement et champs QCM.
  • stats : statistiques de traitement disponibles pour les extensions futures.

Une note professeur validée est prioritaire sur la note LLM dans l'interface et dans le bilan.

Fichiers d'une copie

Dans copies_anonymes_validees/Copie_01/, l'application conserve notamment :

  • Copie_01.pdf : scan individuel, généralement stocké au niveau du dossier parent.
  • extraction.md : transcription complète.
  • pageXX.md : transcription indépendante de chaque page.
  • correction.csv ou les données SQLite : résultat de correction selon le workflow utilisé.

Configuration API et endpoints

Les providers sont configurés dans correct_ai/llm_providers.py. Chaque configuration indique l'URL compatible OpenAI, le modèle, la variable de clé API et la vérification TLS.

Le provider par défaut est défini par DEFAULT_PROVIDER. Les appels disposent d'un timeout de 600 secondes ; les modèles Qwen peuvent utiliser le mode thinking.

Endpoints de données

  • GET /api/db/bareme : récupérer le barème depuis SQLite.
  • GET /api/db/copies : lister les copies et les métadonnées étudiants.
  • GET /api/db/corrections/<copie_id> : récupérer les corrections d'une copie.
  • POST /api/db/corrections/<copie_id> : enregistrer les corrections professeur.
  • GET /api/bilan/stats : obtenir les statistiques globales.
  • POST /api/bilan/export-graphs : sauvegarder les graphiques PNG exportés dans graphiques_notes/.
  • GET /api/project/check : vérifier les fichiers du projet et compter les copies.

Commandes CLI et Makefile

Les commandes courantes sont regroupées dans le Makefile :

make help       # afficher les commandes
make run        # lancer l'application
make test       # exécuter les tests
make compile    # vérifier la syntaxe Python
make check      # compiler puis tester
make format     # appliquer isort et black

Générer le barème

uv run python correct_ai/subject_analysis.py --project-dir mon_projet

Les marqueurs de question du sujet suivent la forme (--Qx.y) et doivent être placés après le texte de chaque question.

Correction incrémentale

uv run python correct_ai/batch_correction_v2.py \
  --project-dir mon_projet --start 1 --end 31

# Mode test sans appel LLM réel
uv run python correct_ai/batch_correction_v2.py \
  --project-dir mon_projet --start 1 --end 5 --test-mode
  • --start et --end : plage inclusive.
  • --provider : provider LLM à utiliser.
  • --test-mode : réponse mockée sans appel réseau.

La correction v2 prend en compte un échantillon de copies précédentes, applique un budget de contexte et effectue des tentatives de reprise en cas d'échec.

Vérification OCR

L'onglet Vérif OCR permet de vérifier et corriger manuellement l'extraction :

  • visualisation page par page des PDF ;
  • édition du Markdown extrait ;
  • prévisualisation avec rendu LaTeX par MathJax ;
  • sauvegarde et annulation des modifications ;
  • détection des erreurs courantes de LaTeX ;
  • reconstruction de extraction.md à partir des pages.
