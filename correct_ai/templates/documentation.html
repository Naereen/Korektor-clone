Guide de l'application

Korektor

Assistant IA pour la correction de copies manuscrites.

Cette page reprend la documentation du projet et décrit le parcours complet, de l'import du scan au bilan des notes.

Logiciel créé par Philippe HELLUY, et modifié par Lilian BESSON (@Naereen). Mon fork est disponible sur GitHub (dépôt privé).

Fonctionnalités

  1. Numérisation et import : import direct de scans A4 ou découpage intelligent de scans A3 vers A4, avec nombre de pages par copie configurable, puis regroupement par étudiant.
  2. Structuration du sujet : analyse du sujet et du corrigé pour générer un barème structuré avec questions, réponses attendues et points.
  3. Vérif Barème : relecture et modification du barème CSV avant le découpage et la correction.
  4. Extraction OCR : transcription du contenu manuscrit en Markdown avec structuration assistée par LLM.
  5. Correction IA : notation assistée avec notes, commentaires, raisonnement et contexte des copies précédentes.
  6. Vérification professeur : relecture des copies, ajustement des notes et validation des corrections.
  7. Bilan : suivi des copies corrigées, des notes brutes, des notes reconverties sur 20 et visualisations exportables en PNG.
  8. Livret individuel : génération d'un PDF A4 avec notes, corrigé, appréciations et extraits annotés de la copie lorsqu'ils existent.

Installation

Prérequis : Python 3.12 ou plus récent et uv.

Créer l'environnement virtuel et installer les dépendances :

uv venv
source .venv/bin/activate
uv sync

Les dépendances et les groupes de développement sont déclarés dans pyproject.toml. Une installation historique reste possible avec :

uv pip install -r requirements.txt

Définir ensuite une clé API correspondant au provider utilisé, par exemple :

export UNISTRA_API_KEY="votre_cle_ici"
# ou, selon le provider :
export ILAAS_API_KEY="votre_cle_ici"

Utilisation

Lancer l'application

make run
# ou
uv run python correct_ai/app.py

L'interface est accessible sur http://127.0.0.1:5000.

Configurer un projet

  • Le dossier de travail par défaut est ./exemple.
  • Le dossier actif peut être changé depuis l'onglet Import.
  • Les dossiers validés sont conservés dans ce navigateur : Double-cliquez dans le champ ou appuyez sur la flèche vers le bas pour retrouver les chemins récents. La saisie manuelle et le sélecteur de dossier restent disponibles.
  • Les fichiers principaux sont sujet.md, corrige.md et liste-etudiants.csv.
  • bareme.csv est généré depuis l'onglet Import. L'onglet Vérif Barème permet de le relire et de le modifier, y compris pour les réponses sur plusieurs lignes. Les changements enregistrés sont aussi reportés dans korektor.db si cette base existe déjà.

Parcours recommandé

  1. Import : sélectionner le projet, vérifier les fichiers, générer le barème et importer le PDF. Conserver l'option PDF déjà en A4 pour un scan A4 ; la décocher pour découper des feuilles A3. Indiquer aussi le nombre de pages A4 par copie : la valeur proposée est 2 en import A4 et 4 en mode livret.
  2. Vérif Barème : rechercher et filtrer les questions, modifier leur type, leurs points et leurs réponses dans l'éditeur CodeMirror. Ajouter ou réordonner les questions puis enregistrer avant le découpage. Une question déjà corrigée ne peut pas être supprimée.
  3. Découpage : valider les débuts de copie et l'identification des étudiants. La taille choisie à l'import détermine les aperçus affichés et le nombre de pages incluses dans chaque PDF individuel.
  4. OCR : lancer l'extraction sur une plage de copies. La case Forcer permet de recalculer les extractions existantes.
  5. Vérif OCR : relire et corriger le texte page par page dans l'éditeur CodeMirror Markdown, avec numéros de ligne.
  6. Correction : lancer la correction incrémentale. La case Forcer permet d'écraser les corrections existantes.
  7. Vérif Correction : contrôler les réponses, les commentaires, le raisonnement et les notes. Si une question possède un extrait manuscrit annoté, afficher son image et ses zones d'erreur. Le bouton Générer & Voir le PDF Élève enregistre les modifications en attente avant d'ouvrir un livret actualisé dans un nouvel onglet.
  8. Bilan : consulter l'état global, les notes, les copies incomplètes et les graphiques de l'évaluation. Le bouton Générer tous les PDF Élèves (Typst) produit les livrets dans exports_pdf/ ; la colonne PDF élève permet de télécharger le livret à jour de chaque copie.

Les étapes automatiques enchaînent directement sur la suivante après un succès : Import vers Vérif Barème, Vérif Barème vers Découpage après enregistrement, Découpage vers OCR, OCR vers Vérif OCR, puis Correction vers Vérif Correction. Les pages de relecture proposent une action explicite pour sauvegarder avant d'avancer. Le Bilan contient un accès direct aux Rapports. En cas d'annulation ou d'erreur, la page courante est conservée afin de consulter les journaux ou de reprendre le travail.

Graphiques du bilan

La page Bilan affiche les visualisations suivantes :

  • Distribution des notes / 20 : histogramme des notes finales par tranches de 1 point.
  • Difficulté des questions : pourcentage moyen de points obtenus pour chaque question.
  • Profil moyen de la classe : comparaison, question par question, entre le barème et la moyenne obtenue par la classe.
  • Dispersion par question : distributions en violon avec points individuels, boîte à moustaches et moyenne, dans une zone dimensionnée pour garder le titre entièrement visible.
  • Résultats détaillés : comparaison du barème et des points obtenus par un étudiant sélectionné ou par la moyenne de la classe.

Chaque graphique peut être téléchargé individuellement en PNG. Le bouton Exporter tous les graphiques en PNG, situé en haut de la page, sauvegarde l'ensemble des graphiques dans le sous-dossier graphiques_notes/ du projet actif. Les images sont générées avec un fond blanc.

Structure des données

Base SQLite : korektor.db

La base conserve les informations nécessaires à la correction et à la validation :

  • sujet : contenu du sujet.
  • corrige : corrigé officiel.
  • bareme : questions, types, réponses attendues et points.
  • copies : métadonnées, PDF, extraction OCR et état de vérification.
  • corrections : notes LLM, notes professeur, commentaires, raisonnement et champs QCM, ainsi que crop_image_path et bounding_boxes pour les annotations spatiales.
  • stats : statistiques de traitement disponibles pour les extensions futures.

Une note professeur validée est prioritaire sur la note LLM dans l'interface et dans le bilan.

Les zones annotées sont enregistrées en JSON sous la forme [{"bbox_2d": [ymin, xmin, ymax, xmax], "label": "Erreur", "page": 2}]. Les coordonnées entières vont de 0 à 1000 sur chaque page ; le numéro de page commence à 1 et est nécessaire pour recadrer un PDF multipage. La première zone exploitable de chaque question peut produire un PNG dans cropped_questions/. Si le PDF manque ou que la page ne peut pas être identifiée, les boîtes restent enregistrées sans chemin d'image.

Fichiers d'une copie

Dans copies_anonymes_validees/Copie_01/, l'application conserve notamment :

  • Copie_01.pdf : scan individuel, généralement stocké au niveau du dossier parent.
  • extraction.md : transcription complète.
  • pageXX.md : transcription indépendante de chaque page.
  • correction.csv ou les données SQLite : résultat de correction selon le workflow utilisé.

Le fichier .korektor_split.json, placé à la racine du projet, mémorise le nombre de pages A4 par copie choisi lors du dernier import. Pour assurer la compatibilité, un projet qui ne possède pas encore ce fichier utilise 4 pages par copie.

Livret PDF individuel (Typst)

Le module correct_ai.pdf_builder génère un livret A4 par étudiant depuis korektor.db : nom, prénom, note globale, moyenne des copies notées, énoncé et corrigé par question, appréciation et, si disponible, recadrage du scan avec ses annotations rouges. Les notes validées par le professeur priment sur celles de l'IA.

La bibliothèque Python typst compile directement le PDF, sans exécutable Typst séparé. Les caractères Unicode et les notations mathématiques sont affichés comme du texte, sans interprétation du contenu comme code Typst.

Le livret utilise la police TeX Gyre Pagella, proche de Palatino. Sous Debian/Ubuntu, elle est fournie par fonts-texgyre ; en son absence, Typst utilise DejaVu Sans comme police de repli.

from correct_ai.pdf_builder import generate_student_pdf

generate_student_pdf(
    copie_id=1,
    db_path="exemple/korektor.db",
    output_pdf_path="rapports_pdf/Copie_01.pdf",
)

Un chemin de sortie relatif est résolu depuis le dossier du projet. Le JSON et les images utilisés pour la compilation sont temporaires et supprimés une fois le PDF généré.

Configuration de l'API et des points de terminaison

Les providers sont configurés dans correct_ai/llm_providers.py. Chaque configuration indique l'URL compatible OpenAI, le modèle, la variable de clé API et la vérification TLS.

Le provider par défaut est défini par DEFAULT_PROVIDER. Les appels disposent d'un timeout de 600 secondes ; les modèles Qwen peuvent utiliser le mode thinking.

Endpoints de données

  • GET /api/db/bareme : récupérer le barème depuis SQLite.
  • GET /api/db/copies : lister les copies et les métadonnées des étudiants.
  • GET /api/db/corrections/<copie_id> : récupérer les corrections d'une copie, avec l'identifiant de chaque correction, son éventuel crop_image_path et ses bounding_boxes décodées en liste pour l'aperçu annoté.
  • POST /api/db/corrections/<copie_id> : enregistrer les corrections professeur.
  • GET /api/bilan/stats : obtenir les statistiques globales.
  • POST /api/bilan/export-graphs : sauvegarder les graphiques PNG exportés dans graphiques_notes/.
  • GET /api/project/check : vérifier les fichiers du projet et compter les copies.
  • GET /api/copies/<copie_id>/pdf : générer ou afficher dans le navigateur le livret Typst individuel ; le PDF existant dans exports_pdf/ est réutilisé. Ajouter ?refresh=1 pour recompiler après une correction et télécharger un exemplaire à jour.
  • POST /api/copies/generate-all-pdfs : régénérer tous les livrets dans exports_pdf/ et renvoyer le nombre de réussites.
  • GET /api/corrections/<correction_id>/crop : afficher le PNG manuscrit annoté associé à une correction.

Le lot renvoie un JSON avec generated, total et errors. Une ressource absente produit une erreur JSON 404 ; un échec de génération, y compris partiel, renvoie une erreur JSON 500 détaillant les copies concernées.

Commandes CLI et Makefile

Les commandes courantes sont regroupées dans le Makefile :

make help       # afficher les commandes
make run        # lancer l'application
make test       # exécuter les tests
make compile    # vérifier la syntaxe Python
make check      # compiler puis tester
make format     # appliquer isort et black

Générer le barème

uv run python correct_ai/subject_analysis.py --project-dir mon_projet

Les marqueurs de question du sujet suivent la forme (--Qx.y) et doivent être placés après le texte de chaque question.

Correction incrémentale

uv run python correct_ai/batch_correction_v2.py \
  --project-dir mon_projet --start 1 --end 31

# Mode test sans appel LLM réel
uv run python correct_ai/batch_correction_v2.py \
  --project-dir mon_projet --start 1 --end 5 --test-mode
  • --start et --end : plage inclusive.
  • --provider : provider LLM à utiliser.
  • --test-mode : réponse mockée sans appel réseau.

La correction v2 prend en compte un échantillon de copies précédentes, applique un budget de contexte et effectue des tentatives de reprise en cas d'échec.

Vérification OCR

L'onglet Vérif OCR permet de vérifier et corriger manuellement l'extraction :

  • visualisation page par page des PDF ;
  • édition du Markdown extrait avec CodeMirror, coloration Markdown, numéros de ligne et retour automatique à la ligne ;
  • prévisualisation avec rendu LaTeX par MathJax ;
  • sauvegarde et annulation des modifications ;
  • détection des erreurs courantes de LaTeX ;
  • reconstruction de extraction.md à partir des pages.
